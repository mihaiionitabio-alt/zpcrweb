# 2026.10.26.voiceworkspace1

Voice start/stop/meter now follow the workspace and Console, with existing setup behavior retained. Closing Console no longer stops listening by itself; Stop, timeout and page hiding still stop it. Outside Console, numeric commands 1–8 select the existing views and 0 opens Console. Console number behavior remains unchanged.

112 chart definitions have stable numbers within this release: control catalogue order first, then single-run graph catalogue order. Numbers may change if a future catalogue changes; they are not persistent acquisition IDs. Say “Computer show chart 17”, “Computer list charts”, “Computer analyze this chart”, “Computer status report”, or “Computer full report”. Numbers through 199 can be spoken in English; digit transcripts accept up to three digits. Single-run selectors and control detail panels show the numbers.

Current control-chart replies read the existing ccCompute result, point flags, specifications and baseline readiness. They count flagged points separately from points beyond available limits. Missing values, pre-baseline points and unavailable assessment are disclosed. General graphs without this existing assessment explicitly do not receive a nominal verdict. This is not a whole-dataset outlier/diagnosis engine.

Status observations name their source and rule/basis identifier. Software faults are distinguished from sample failures. Short and full reports disclose the assessment coverage. Read-only questions include filenames, sample names, device time, session duration, browser-reported JavaScript heap, visible-table descriptions, row reading and strict numeric displayed-column summaries. Displayed-column summaries do not convert units, classify results, parse decorated text into numbers, or count blank strings as zero. Original sample names may be spoken, per the user's explicit preference; export pseudonymisation is unchanged.

The 122-pair readiness register is explicit: 44 working routes, 10 boundary replies, 68 recognized requests with an honest not-yet-implemented response. It does not claim 122 fully implemented scientific capabilities. Empty-dataset routing tests cover every pair; loaded-data tests separately verify the actual chart/fact handlers. No example counts, false-positive hardware diagnoses or canned results were imported. Freeze/resume, investigator edits, voice exports and automatic result changes are not implemented by this update.

Charts default dark; a small sun/moon button and “Computer white background” / “Computer dark background” change the screen presentation only. CSS also covers the interactive Plotly surface. Existing Console theme actions remain available. Theme selection is persisted locally. Graph and report exports keep their existing rendering and values; theme CSS is not serialized into existing SVG export strings.

“Computer highlight this chart” and chart/report answers highlight the current chart for five seconds. Existing SVG marker tooltips tied to recorded flags can receive a marker outline; other charts receive a container outline only. Highlights are DOM presentation, not additional scientific flags or export changes. Reduced-motion users receive a static outline. The highlight never claims to identify a point lacking a verified renderer binding.

Validation: Chrome boot, all eight workspace views, Console reparenting, numbered chart opening, exact existing flag counts, 122 phrase routes, stable recognition and barge-in regression, five-second highlight, reduced motion, unchanged SVG export and numerical snapshots. Format comparisons are recorded separately. Recognition was emulated; no physical-microphone transcription accuracy is claimed. Decoded PCRD was not rerun because the decoder key was not provided; its reader implementation is byte-identical.

The publication version is separately labelled from the historical scientific APP_VERSION. This preserves existing scientific export metadata. The current publication meta and identity labels show this release. Full font coverage and sound synthesis are unchanged. All additions remain within one offline HTML file.
