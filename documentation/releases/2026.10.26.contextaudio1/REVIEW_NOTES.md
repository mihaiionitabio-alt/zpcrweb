# Review input disposition

The supplied modules were considered, not installed alongside the existing engine. A second engine would duplicate contexts and settings. Their measured-energy approach, forced previews, explicit acknowledgement gate and missing-value concern informed the changes. Their 140-cue verification claims were not independently asserted here; this release measures its own 513-entry catalogue.

The original answer failure was traced to a context guard after Console controls refreshed. Read-only answers now read current state at execution time; numbered actions retain stale-context protection. The two acknowledgements in that test were produced after deliberate clock advances, not evidence that the gate failed. The new gate test explicitly checks the next wake and reload behavior, plus a wedged acknowledgement timeout.

Scientific spoken templates were not installed: their state fields differ from this application's fields; equality to protocol cycle count is not sufficient by itself to classify a source value as a no-amplification token; an encrypted PCRD may be unlocked rather than necessarily skipped; and a download click does not prove a file was saved. Question answers use existing state or the requested limited-response fallback. Installed speech voices must be localService; default/remote voice fallback is not used.

The serial mix is deliberate. Parallel multi-input mixing had produced low-bit differences; fixed-order unity-gain summation passes strict canonical PCM comparison. The remaining signed-zero distinction is explicitly normalized only in the test hash, with raw hashes retained. Audio changes are listed separately from validation changes in RELEASE.md. No scientific sample values are normalized by this audio hash method.
