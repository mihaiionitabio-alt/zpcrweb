# Stable offline voice commands — 26 October 2026

The live Chrome recognizer emitted provisional “Two” results without finalizing them. The previous final-only handler ignored them. Recognition now requests interim results and accepts an unambiguous command after 700 ms without a candidate change, or immediately on a final result. Each recognition result index can act only once, including repeated words, later transcript updates and finalization. A separate recognition segment can issue another command. Stop/session generation and menu-context checks prevent stale timers from acting.

Whole English words zero–fifteen and digits are recognized among filler words. On the main Console action row, next/forward/advance mean Next; previous/back/backward mean Previous. Aliases do not select numbered submenu entries. Conflicting distinct commands, negation words, and substrings such as “forwarding” are ignored. This is an explicit keyword interface, not an intent-understanding system: unrelated conversation containing a permitted keyword may act while listening. Pause voice when conversing.

Chrome automated tests passed for stable provisional commands, changing candidates, repeated interim/final deduplication, aliases within filler speech, conflicts, negation, whole-word matching and stopping before a timer fires. These tests emulate recognition events; the original fault was captured from real microphone recognition in interactive Chrome. Revised physical-microphone transcription is not claimed as tested.
